## 🐛 Bug 修复

### [B1] tool-treesize schema 启动失败 + 视频库加载不全双修

- **预估工时**：0.5h
- **现象**：F4 commit 后用户反馈 Spring Boot 启动报 `[SQLITE_ERROR] SQL error or missing database (incomplete input)`；强行启动后视频库列表加载不全
- **根因**：
  1. `treesize-schema.sql` 新增 ext 列时的多行注释里写了分号（`idx_node_video_ext_size;`），`SchemaInitializer.splitStatements` 是简陋的 `String.split(";")` 不识别 SQL 注释，把注释里的分号当语句分隔符 → CREATE TABLE 半截被截断
  2. F4 backfill 用 `WHERE is_dir = 0 AND ext IS NULL LIMIT 10000` 反复全表扫，N² 越后越慢；若中途 SQLite busy 超时抛异常被外层 catch 吞掉，部分行 ext 仍为 NULL → 被 `n.ext IN (...)` 永久过滤
- **修改明细**：
  - `02:10` schema.sql ext 列注释去分号（改为「(TreeSizeMigration adds this column on pre-existing databases)」），扫描整文件确认无其他注释含分号
  - `02:20` 新建 MigrationStatus @Component：`volatile boolean extBackfillDone`，包私有 markExtBackfillDone()
  - `02:25` TreeSizeMigration 注入 MigrationStatus + VideoLibraryCountCache，run() 末尾 markExtBackfillDone + countCache.invalidateAll；catch 块仅 log 不 mark（失败时保持 legacy 路径）
  - `02:30` backfillExt 改游标式：`WHERE id > ? AND is_dir = 0 AND ext IS NULL ORDER BY id LIMIT ?`，cursor 取 rows.last.id 推进，避免 N²；每 5 个 batch 打 progress 日志
  - `02:40` NodeRepository 注入 MigrationStatus，提取 appendExtensionFilter / nameOrSizeOrderExpr 两个 helper：未完成走旧 `LOWER(n.name) LIKE '%.mp4' OR ... × 19` + `ORDER BY LOWER(name)` 兜底，完成后走新 `n.ext IN (...)` + `ORDER BY n.name COLLATE NOCASE`；findVideos / countVideos / findJunkVideos 全部走 helper
  - `02:48` mvn compile 通过
