## 1. 核心业务规则

- 房间号 trim 后 1-64 字符，正则 `^[a-zA-Z0-9_\-一-龥]+$`
- 房间最大 10 人，超出返回 `room-full`
- 同 deviceId 重复 join 视为重连：关旧 WS、替换 session、**不**广播 peer-joined
- 后端不解析 `signal.payload`，按 `to` 透传；不限频
- 分片固定 16KB；`bufferedAmount > 16MB` 暂停，等 `onbufferedamountlow`（阈值 1MB）
- 多文件并发共用一对 control/data DC，按 fileId 路由
- 完整性校验：仅判 chunkCount 一致，不做哈希
- 建链超时 10s，失败关 PC 报错，**不**自动重试
- ICE 仅 STUN，不部署 TURN

## 5. 重要约束与边界

- **并发安全**：`Room` 内所有成员变更操作必须在 `synchronized(this)` 块内完成；快照返回前完成全部修改
- **事务范围**：无数据库事务；纯内存
- **幂等键**：`deviceId`——同 deviceId 二次 join 视为重连，自动替换旧 session
- **不处理的场景**：双对称 NAT 失败、4G 跨运营商、企业防火墙限 UDP——前端 UI 报"无法建立直连"即可，**不**降级到 HTTP 中转
- **背压实现**：发送循环每写一片后检查 `dataDC.bufferedAmount`；超阈值时 `await onbufferedamountlow` 一次性 promise，再继续
- **资源释放**：传输 complete 后立即 `URL.revokeObjectURL`；PC `connectionState` 变 closed/failed 时关闭对应 DC

## 7. 异常处理要点

### 后端

| 场景 | 行为 |
|------|------|
| 入站 JSON 解析失败 | 发送 `error: invalid-payload`，不关闭 WS |
| 未 join 直接 signal/leave | 发送 `error: not-in-room` |
| join 时房间号格式不合法 | 发送 `error: invalid-payload` 后关闭 WS |
| 房间已满 10 人 | 发送 `error: room-full` 后关闭 WS |
| signal 的 to 不在房间 | 发送 `error: peer-not-found`，不关闭 WS（双方都能继续工作） |
| WebSocketSession.sendMessage 抛 IOException | catch 并 log，标记 session 失效，触发 leave |

### 前端

| 场景 | 行为 |
|------|------|
| `WebSocket.onerror` / `onclose` | 5s 重连，最多 3 次；之后 UI 显示"信令断开" |
| `RTCPeerConnection.connectionState = failed` | 关闭 PC，传输标记 failed，UI 给"无法建立直连" |
| 建链 10s 内未 connected | 主动 close PC，同上 |
| `onicecandidateerror` | 仅 log，不影响（其他 candidate 仍可能成功） |
| 接收方 chunkCount 校验失败 | 标记 failed，告知发送方 reject |
| 用户拒绝接收 | 发 `reject`，发送方清理 fileId 状态 |
| 文件 > 1GB | UI 警告但不阻止（仅前端校验，后端不参与） |

## 8. 实施顺序建议

1. **先打通信令**：后端 `WebSocketConfig` + `SignalingWebSocketHandler` + `RoomRegistry` + `Room` + `DeviceSession`，前端 `signalingClient`，能 join + 互看名册即可
2. **再打通建链**：前端 `peerConnectionManager`，两端 connectionState=connected 即过关
3. **最后实现传输**：前端 `fileTransfer`（先 1MB 小文件），调通后再压力测试 100MB / 1GB
4. **UI 收尾**：所有组件、`useRoom` hook、加入 feature manifest
5. **HTTP 端点**：最简单的 `LanShareController`，最后做即可
