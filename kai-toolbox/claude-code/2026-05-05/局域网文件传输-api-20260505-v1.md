## 接口清单

| # | 协议 | 路径 / 端点 | 用途 |
|---|------|-----------|------|
| 1 | HTTP GET | `/api/lan-share/health` | 健康检查 |
| 2 | HTTP GET | `/api/lan-share/ice-config` | 获取 STUN 配置 |
| 3 | WebSocket | `/ws/lan-share` | 信令通道（房间 + SDP/ICE 透传） |

| 5 | DataChannel | P2P data 通道 | 文件二进制分片 |

## 1. 健康检查

### 1.1 基本信息

- **方法**：`GET`
- **路径**：`/api/lan-share/health`
- **用途**：前端 WS 断线探活
- **认证**：无
- **幂等**：是

### 1.2 请求

无入参。

### 1.3 响应

#### 成功（200）

```
HTTP/1.1 200 OK
```

返回体可空。

### 1.4 示例

```http
GET /api/lan-share/health HTTP/1.1
```

```http
HTTP/1.1 200 OK
```

## 2. 获取 ICE 配置

### 2.1 基本信息

- **方法**：`GET`
- **路径**：`/api/lan-share/ice-config`
- **用途**：将 STUN 列表服务端化，方便后续切换 STUN 提供商而不必发版前端
- **认证**：无
- **幂等**：是

### 2.2 请求

无入参。

### 2.3 响应

#### 成功（200）

```json
{
  "iceServers": [
    { "urls": "stun:stun.l.google.com:19302" }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `iceServers` | array | 与 `RTCPeerConnection` 构造参数兼容的 ICE 服务器配置 |
| `iceServers[].urls` | string | ICE 服务器地址，`stun:` / `turn:` 协议前缀 |

### 2.4 示例

```http
GET /api/lan-share/ice-config HTTP/1.1
```

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "iceServers": [
    { "urls": "stun:stun.l.google.com:19302" }
  ]
}
```

## 附录 A：WebSocket 信令接口

### A.1 端点信息

- **路径**：`ws://localhost:8080/ws/lan-share`
- **协议**：原生 WebSocket（不使用 STOMP）
- **认证**：无
- **消息载荷**：JSON 文本

### A.2 客户端 → 服务端消息

#### A.2.1 `join`

- **方向**：C→S
- **触发**：用户进入房间页面，点击"加入"按钮

```json
{
  "type": "join",
  "roomId": "abc",
  "deviceId": "uuid-aaa",
  "nickname": "我的电脑"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 固定 `"join"` |
| `roomId` | string | 是 | trim 后 1-64 字符，正则 `^[a-zA-Z0-9_\-一-龥]+$` |
| `deviceId` | string | 是 | UUID v4，前端 localStorage 持久化 |
| `nickname` | string | 是 | trim 后 1-32 字符，允许中英文符号 |

#### A.2.2 `leave`

- **方向**：C→S
- **触发**：用户主动点击"离开"按钮（WS 关闭等价于 leave）

```json
{ "type": "leave" }
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 固定 `"leave"` |

#### A.2.3 `signal`

- **方向**：C→S
- **触发**：本端 RTCPeerConnection 产生 offer / answer / ICE candidate

```json
{
  "type": "signal",
  "to": "uuid-bbb",
  "payload": { "kind": "offer", "sdp": "..." }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 固定 `"signal"` |
| `to` | string | 是 | 目标设备 deviceId，必须与本设备处于同一房间 |
| `payload` | object | 是 | 透传载荷，服务端不解析。常见 `kind`：`offer` / `answer` / `ice` |

### A.3 服务端 → 客户端消息

#### A.3.1 `joined`

- **方向**：S→C
- **触发**：服务端处理完 `join`，向加入者返回当前房间名册

```json
{
  "type": "joined",
  "self": "uuid-aaa",
  "peers": [
    { "deviceId": "uuid-bbb", "nickname": "我的手机", "joinedAt": 1730000000000 }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `self` | string | 自身 deviceId（确认服务端识别） |
| `peers` | array | 房间内除自己之外的成员，含 deviceId / nickname / joinedAt（毫秒时间戳） |

#### A.3.2 `peer-joined`

- **方向**：S→C
- **触发**：有新成员加入本房间，向所有原成员广播

```json
{
  "type": "peer-joined",
  "peer": { "deviceId": "uuid-ccc", "nickname": "平板", "joinedAt": 1730000100000 }
}
```

#### A.3.3 `peer-left`

- **方向**：S→C
- **触发**：有成员离开本房间（leave 或 WS close）

```json
{ "type": "peer-left", "deviceId": "uuid-ccc" }
```

#### A.3.4 `signal`（转发）

- **方向**：S→C
- **触发**：服务端将其他成员的 `signal` 透传给本端

```json
{
  "type": "signal",
  "from": "uuid-aaa",
  "payload": { "kind": "offer", "sdp": "..." }
}
```

#### A.3.5 `error`

- **方向**：S→C
- **触发**：协议错误或业务边界错误

```json
{ "type": "error", "code": "peer-not-found", "message": "目标设备不在房间内" }
```

| 错误码 | 触发场景 |
|--------|---------|
| `peer-not-found` | `signal` 的 `to` 字段不在本房间 |
| `room-full` | 房间已满 10 人，新成员被拒 |
| `invalid-payload` | join 时房间号 / 昵称格式不合法 |
| `not-in-room` | 未 join 直接发 signal / leave |

## 附录 B：DataChannel 协议（P2P）

每对建立连接的 peer 之间打开**两条** DataChannel：

| 名称 | 模式 | 用途 |
|------|------|------|
| `control` | text，ordered，reliable | JSON 文本控制消息 |
| `data` | binary，ordered，reliable | 文件二进制分片帧 |

### B.1 control 消息

#### B.1.1 `offer`

- **方向**：发送方 → 接收方
- **触发**：发送方点击"发送文件"

```json
{
  "type": "offer",
  "fileId": "uuid-fff",
  "name": "report.pdf",
  "size": 12345678,
  "mime": "application/pdf",
  "totalChunks": 754
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `fileId` | string | 是 | UUID v4，本次传输唯一标识 |
| `name` | string | 是 | 文件名 |
| `size` | integer | 是 | 字节数 |
| `mime` | string | 否 | MIME，便于接收方下载时设置 Content-Type |
| `totalChunks` | integer | 是 | 分片总数（`Math.ceil(size / 16384)`） |

#### B.1.2 `accept`

- **方向**：接收方 → 发送方
- **触发**：用户在 IncomingDialog 点击"接受"

```json
{ "type": "accept", "fileId": "uuid-fff" }
```

#### B.1.3 `reject`

- **方向**：接收方 → 发送方
- **触发**：用户拒绝或超时未响应

```json
{ "type": "reject", "fileId": "uuid-fff", "reason": "user-declined" }
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `reason` | string | 否 | `user-declined` / `timeout` / `quota-exceeded` 等 |

#### B.1.4 `progress`

- **方向**：接收方 → 发送方
- **触发**：每收到 ~50 片上报一次

```json
{ "type": "progress", "fileId": "uuid-fff", "received": 1638400 }
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `received` | integer | 已接收字节数 |

#### B.1.5 `complete`

- **方向**：接收方 → 发送方
- **触发**：所有分片到齐、chunkCount 校验通过、Blob 拼装完成

```json
{ "type": "complete", "fileId": "uuid-fff" }
```

#### B.1.6 `cancel`

- **方向**：任一方
- **触发**：用户主动取消传输

```json
{ "type": "cancel", "fileId": "uuid-fff" }
```

### B.2 data 帧（二进制）

每帧固定头部 20 字节 + 可变 payload（最大 16384 字节）：

```
+---------------+----------------+----------------+
| fileId 16 B   | chunkIdx 4 B   | payload ≤16KB  |
| (UUID 二进制)  | (大端 uint32)   | (文件分片字节)  |
+---------------+----------------+----------------+
```

| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0 | 16 | `fileId` | UUID v4 二进制（与 control 消息中的 fileId 一致） |
| 16 | 4 | `chunkIdx` | 大端 uint32，从 0 开始 |
| 20 | ≤16384 | `payload` | 该片的文件字节，最后一片可能不足 16KB |

**接收方处理**：
1. 读 16 字节 → 还原 fileId
2. 读 4 字节 → 还原 chunkIdx
3. 剩余字节 → 写入 `chunks[fileId][chunkIdx]`
4. 当 `chunks[fileId].filter(Boolean).length === totalChunks` → 拼装 Blob
